# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Workflow

- **Never commit on your own initiative.** Run `git commit` only when explicitly asked to in
  that turn — an approved plan is not approval to commit, and neither is having been asked
  earlier in the session. Finish the work, run the checks, report what changed, and leave the
  changes in the working tree for review. The same restraint applies to pushing and opening PRs.

## Project

**Elysian** — a modular, ACF-first WordPress **starter theme**, reused as the base of new
client projects. Content is built almost entirely from ACF (Advanced Custom Fields PRO)
Gutenberg blocks; core blocks are disabled by default. SCSS/JS are compiled with a Gulp 5
pipeline.

**Starter vs. project.** The header, footer, Theme Settings, build, tools and conventions
are the starter. The live blocks are project-specific, and a new project deletes them (see
[Starting a new project](#starting-a-new-project-from-this-starter)). The reusable
patterns live on in **[_dev/examples/](_dev/examples/README.md)**: inert reference copies of every
block built so far. **Always start a new block from the closest example.**

Working notes for Claude (read when the task touches them):
- [_dev/docs/figma-to-block.md](_dev/docs/figma-to-block.md): the full Figma → block playbook and the pitfalls already hit
- [_dev/docs/wp-scripting.md](_dev/docs/wp-scripting.md): ACF groups, menus and page content from the terminal

- Text domain: `elysian-theme`
- Function prefix: `elysian_theme_` (use it for every new theme function)
- Requirements: WordPress 5.0+, PHP 7.4+, **ACF PRO**, Node 22.22.3+ / 24.15+ / 26+
- Full reference: see [readme.md](readme.md)

## Commands

Run from the theme root.

| Command | What it does |
|---|---|
| `npm install` | Install build dependencies (first time) |
| `npm start` / `npm run dev` | Dev build + watch + BrowserSync live reload |
| `npm run build` | One-time dev build (sourcemaps, unminified). Fonts + favicon regenerate **only if missing or their source changed** |
| `npm run prod` | Production build: clean compiled `css/js/img`, regenerate fonts + favicon **only if missing/changed**, then minified assets (`drop_console`, no sourcemaps). Fonts/favicon are preserved across runs — use `npm run clean` first to force a full rebuild |
| `npm run quick` | Minified asset build only — no clean, favicon, watch or serve. Ensures fonts exist first (regenerates **only if missing/changed**) so SCSS `@use 'base/fonts'` never fails |
| `npm run clean` | Delete `dist/` (full wipe, incl. fonts + favicon) |
| `npm run lint` | Lint SCSS (Stylelint) + JS (ESLint) |
| `npm run lint:fix` | Auto-fix lint issues |
| `npm run shot -- <selector> [widths…]` | Screenshot one element (default 1440 + 375) into `_dev/tools/visual/out/`. Options: `--path=/page/`, `--url=…` |
| `_dev/tools/wp/run.sh -e '<php>'` / `<file.php>` | Run PHP with WP + ACF loaded against this Local site (no wp-cli; finds the MySQL socket itself). Recipes in [_dev/docs/wp-scripting.md](_dev/docs/wp-scripting.md) |
| `npm run package` | Production build, then an **allowlisted** upload-ready copy + zip in `_dev/release/` (checks block.json paths and `php -l`). See readme → Deploying |
| `npm run styles:snapshot` / `styles:diff` | Record, then compare, every computed style + box in the header, footer and each `.block` at 375/767/768/1023/1024/1440 (+ mobile menu open). For pure CSS refactors: the diff must report 0 |

**Always run `npm run lint` (and a build) before considering frontend work done.**
Lint is currently clean (exit 0) — keep it that way, so any error is a new one.
BrowserSync proxies `PROXY_URL` from `.env` (copy from `.env.example`).

The visual tools (`_dev/tools/visual/`) drive headless Chrome over the DevTools protocol with
no npm dependency; they read the site URL from `PROXY_URL` (`CHROME_PATH` overrides the
browser). Compare `npm run shot` output against the Figma screenshot before calling a
block done; run `styles:snapshot` **before** a CSS refactor and `styles:diff` after.

## Theme root vs. `_dev/`

The theme root holds only what WordPress needs plus the configs that tools must find there
(`package.json`, `gulpfile.mjs`, lint configs, `.env*`). **Everything dev-only goes under
`_dev/`** (docs, examples, tools, release output). Deploys go through `npm run package`,
which copies an allowlist — so when adding a new top-level folder the theme needs **at
runtime**, also add it to `ALLOW_DIRS` in `_dev/tools/package.mjs`.

## Critical: source vs. compiled

- **Edit source only:** `src/scss/`, `src/js/`, `src/img/`.
- **Never edit `dist/` by hand** — it is git-ignored and regenerated by Gulp.
  Hand edits there will be silently overwritten on the next build.
- After editing SCSS/JS, run a build (`npm run build` or keep `npm start` running)
  so `dist/` reflects your changes.

## Architecture

- `functions.php` bootstraps every module in `inc/` via `require_once`, then defines
  shared helpers. PHP logic is split by concern across `inc/*.php` — put new code in
  the matching module (e.g. CPTs → `inc/post-types.php`, hooks/cleanup →
  `inc/custom-hooks.php`), not in `functions.php`.
- Assets load **conditionally** to keep pages light: global → `inc/register-scripts-and-preload.php`;
  per-block → `style` / `script` in the block's `blocks-json/*.block.json`; flexible
  sections → `have_rows('sections')` switch in `inc/register-scripts-and-preload.php`.
- ACF field groups sync as JSON in `acf-json/` (auto export/import). Don't hand-edit
  those files; create/edit field groups in WP Admin and let them export. When scripting
  it instead (`_dev/tools/wp/run.sh`), pass the group array to `acf_import_field_group()`:
  ACF saves it to the DB and writes the JSON itself, exactly like an Admin save.

### Key helpers (in `functions.php`)

- `elysian_theme_enqueue_style_asset($handle, $relative_path, $deps = [], $media = 'all')`
- `elysian_theme_enqueue_script_asset($handle, $relative_path, $deps = [], $args = [])`
  → **Use these instead of raw `wp_enqueue_*`.** They resolve theme paths, skip
  missing files, and version with `filemtime()` for cache busting. Paths are relative
  to the theme root (e.g. `'dist/css/blocks/hero.css'`).
- `elysian_theme_render_image($image_id, $block_id, $size, $class, $priority = 'auto')` — renders
  `wp_get_attachment_image()` with automatic LCP strategy (first block eager +
  `fetchpriority=high`, later blocks lazy).
- `elysian_theme_render_link($link, $class)` — renders an ACF link array as an escaped `<a class="btn …">`.

## Conventions

- **Templating:** always escape output — `esc_html()` for text, `esc_url()` for URLs,
  `esc_attr()` for attributes. Prefer `wp_get_attachment_image()` / `elysian_theme_render_image()`
  over raw `<img>`. Read fields with `get_field('name')`; global/options fields with
  `get_field('name', 'option')`. Guard ACF values defensively (`?:`, `??`).
- **Naming:** block names are `kebab-case` (`hero`, `testimonial`). CSS classes follow
  `.block` + `.<block-name>-block` + `.<block-name>-block-<element>`. Wrap blocks in
  the shared `.block` class. Prefix every ACF field with the block name
  (`faq_title`, `testimonial_items`); repeater sub-fields stay short (`quote`).
- **i18n:** wrap user-facing strings with the `elysian-theme` text domain.
- **SCSS:** layered partials under `src/scss/`. Three top-level entry points:
  `global.scss` (the main stylesheet, enqueued as `dist/css/global.css`), `critical.scss`
  (above-the-fold CSS, **inlined** into `<head>` by `inc/register-scripts-and-preload.php` — never enqueued)
  and `editor.scss` (block editor, via `add_editor_style`). Only shared, underscore-prefixed
  partials (`abstracts/`, `base/`, `layout/`, `components/`, `editor/`) are `@use`d from those entries.
  Block/section/page-template entry files have **no** underscore (e.g. `blocks/hero.scss`),
  so Gulp compiles each one **standalone** to `dist/css/blocks/hero.css` — do **not** `@use`
  them in `global.scss` (that double-loads).
- **Responsive: desktop-first.** Base styles target desktop; smaller screens override
  them with the `breakpoint-down()` mixin (max-width). Use the named breakpoints from
  `$breakpoints` — `'lg'` (1024px) is the main desktop → mobile switch for the header,
  footer and every block; avoid raw px values. Don't use `breakpoint()`
  (min-width) for layout. When a property exists only on desktop, reset it explicitly
  in the `breakpoint-down` block (e.g. `align-items: normal`).
- **SCSS layer order** in `global.scss` / `critical.scss` is abstracts → base →
  `layout/grid` (objects) → `components/` → `layout/` regions (header, footer, sidebar).
  Components come **before** the site regions on purpose: at equal specificity the later
  rule wins, so `.site-header-btn { display: none }` can hide a `.btn` without selector
  hacks. Keep new partials in that order.
- **Colors:** use the tokens in `abstracts/_variables.scss` — `$color-primary`,
  `$color-white`, `$color-bg-dark`, `$color-surface`, `$color-text-muted`, `$color-border`;
  tints via `rgba($token, 0.1)`. Don't hardcode hex values that already have a token.
  Partials and block files must `@use '../abstracts/variables' as *;` themselves.

## Adding an ACF block

Blocks are registered from `block.json` metadata. Every block's metadata lives **flat**
in `blocks-json/` as a single `<block-name>.block.json` file — no per-block subfolder —
while its render template stays in `template-parts/blocks/<block-name>.php`.
`elysian_theme_register_acf_blocks()` in [inc/acf.php](inc/acf.php)
globs `blocks-json/*.block.json`, so **no PHP change is needed to add a block**.

0. **Pick the closest example** in [_dev/examples/README.md](_dev/examples/README.md) (repeater,
   accordion, slider, background image…), copy its `files/` under the new name and rename
   per that README. Follow [_dev/docs/figma-to-block.md](_dev/docs/figma-to-block.md) when the
   source is a Figma frame.
1. `blocks-json/<block-name>.block.json`:
   `"name": "acf/<block-name>"`, `"category": "elysian_theme_blocks"`, per-block assets
   as `"style": [ "file:../dist/css/blocks/<block-name>.css" ]` and
   `"script": [ "file:../dist/js/blocks/<block-name>.js" ]`, and
   `"acf": { "mode": "preview", "renderTemplate": "../template-parts/blocks/<block-name>.php" }`.
   WP loads those assets only on pages that actually contain the block, so the
   `enqueue_assets` callback is no longer used for blocks.
2. The render template `template-parts/blocks/<block-name>.php` (keep the example's
   `$anchor` / `$classes` preamble, escaping and i18n).
3. Add styles in `src/scss/blocks/<block-name>.scss` (no underscore). It compiles
   standalone to `dist/css/blocks/<block-name>.css` — do **not** `@use` it in `global.scss`.
4. Add scripts `src/js/blocks/<block-name>.js` (optional). Use `script`, not `viewScript`
   (front end only), and wrap the logic in `init(scope)` called on `DOMContentLoaded` **and**
   (inside that same listener — `acf` loads after block scripts) via `window.acf.addAction('render_block_preview/type=<block-name>', ($b) => init($b[0]))`:
   ACF injects and re-renders the editor preview after load (see `src/js/blocks/faq.js`).
   **Vendor libraries** (e.g. Swiper in `assets/swiper/`) are registered — not enqueued —
   in `elysian_theme_register_vendor_assets()` ([inc/register-scripts-and-preload.php](inc/register-scripts-and-preload.php)).
   List the handle **before** the block's own file in `block.json` so it only loads with
   the block: `"style": [ "elysian-theme-swiper-style", "file:…" ]`,
   `"script": [ "elysian-theme-swiper", "file:…" ]`. See [_dev/examples/blocks/testimonial](_dev/examples/blocks/testimonial/README.md).
5. The ACF field group, located to `Block == acf/<block-name>` — in WP Admin, or by script
   ([_dev/docs/wp-scripting.md](_dev/docs/wp-scripting.md#create-an-acf-field-group)); either way it
   auto-exports to `acf-json/`. Fresh keys for the group and every field.
6. Build (`npm start` / `npm run build`).

**Two rules that are easy to get wrong:**
- The metadata filename **must end with the literal string `block.json`**. Core does
  `str_ends_with($path, 'block.json')`; anything else (e.g. `hero.json`) is treated as
  a *directory* and WP looks for `hero.json/block.json`, then fails **silently** — the
  block simply never shows up in the inserter.
- `file:` asset paths and ACF's `renderTemplate` resolve relative to the metadata
  file's directory, which is `blocks-json/` for every block — hence the `../` prefix on
  every path. **Metadata filenames must be unique across all blocks**, since they all
  share one directory.

Block CSS is versioned from the `"version"` field in the JSON (core only uses
`filemtime()` when `SCRIPT_DEBUG` is on), so bump it when shipping style changes.

## Adding a flexible-content section

Mirror the block flow but under `template-parts/sections/`, `src/scss/sections/`,
`src/js/sections/`, and register conditional asset loading via the `get_row_layout()`
switch in `elysian_theme_flexible_assets()` in [inc/register-scripts-and-preload.php](inc/register-scripts-and-preload.php).
Use `template-flexible.php` (the `sections` flexible field) as the page template.
Note: `template-parts/sections/` is currently empty — `hero_section` is the wired example.

## Starting a new project from this starter

Run this checklist **only when the user asks** to start a new project / reset the blocks.
Deletion is manual (there is deliberately no reset script). Show the list of files about to
be deleted and get a yes first.

**First, confirm the prerequisites** (readme → Starting a New Project, steps 1–3). The
theme sits in its **final folder name** on a new Local site with ACF PRO active. `.env` has
the new `PROXY_URL`, `npm install` and a build have run, the theme is active, ACF groups are
synced, and a front page is set. Check what you can yourself (`_dev/tools/wp/run.sh -e
'echo get_stylesheet(), " ", home_url(), " ", defined("ACF_PRO") ? "acf-pro" : "NO ACF PRO";'`)
and ask only about the rest. Ask for the new Figma link if it wasn't given.

1. **Delete the live blocks** — everything project-specific:
   - `blocks-json/*.block.json`
   - `template-parts/blocks/*.php`
   - `src/scss/blocks/*.scss`, `src/js/blocks/*.js`
   - icons used only by blocks in `src/img/icons/` (grep `template-parts/` + `src/` first)
   - every ACF field group located to `block == acf/*`, **from the DB and from
     `acf-json/`**: ACF Sync in the quickstart imports them into the new site's database, so
     deleting only the JSON would leave orphaned groups in WP Admin. Use the recipe in
     [_dev/docs/wp-scripting.md](_dev/docs/wp-scripting.md#delete-the-block-field-groups-new-project)
     (`acf_delete_field_group()` removes both). Then verify that only the options groups
     remain (`acf_get_field_groups()`, and `grep -l '"param": "block"' acf-json/*.json` is empty)
   - any block-only vendor registration in `elysian_theme_register_vendor_assets()` that no
     remaining code uses (Swiper stays registered — it is cheap and examples need it)
2. **Keep:** `header.php` / `footer.php` and their partials, Theme Settings + Global blocks
   option groups and pages, `inc/`, `_dev/tools/`, `_dev/docs/`, **`_dev/examples/`**, the build.
3. **Reset project values:** color tokens in `_variables.scss` (from the new Figma),
   the logo/options content, and the **Project notes** section below (new Figma URL,
   palette, decisions). Theme name in `style.css` / text domain only if the user asks.
4. **Verify:** `npm run build`, `npm run lint` (exit 0), front end renders with no blocks
   and no PHP notices, editor inserter shows no stale blocks.

## Starter conventions

Settled with the owner for every project built on this starter — follow these instead of
asking again.

- **Figma has desktop frames only.** Derive mobile by stacking columns and scaling type
  and spacing down (roughly: section padding 140 → 80, h2 48 → 36px, card padding 40 → 24);
  ask when a layout has no obvious stacked form.
- **Breakpoint:** `'lg'` (1024px) is the single desktop → mobile switch for the header,
  footer and every block.
- **Footer:** link columns are the menu locations `footer-menu-1..3` (the menu *name* is
  the column title); social links are the `footer-social` menu; the description and
  copyright are the `footer_description` / `copyright_text` options (Theme Settings).
- **Demo content:** filling a new block with the Figma copy on the front page is fine;
  don't touch the existing blocks there. When a block becomes an example, also save its
  serialized block as `_dev/examples/blocks/<name>/demo-content.html`.
- **Placeholder links** use `#` until real pages exist.
- **Examples grow:** when a new block introduces a pattern no example covers yet, offer
  to add it to `_dev/examples/` (copy into `files/`, write its README, add a row to
  `_dev/examples/README.md`).
- **Commits:** never on your own initiative (see Workflow).

## Gotchas

- Only `acf/*` blocks are allowed in the editor (`allowed_block_types_all` in
  `inc/extras.php`). New blocks must be ACF blocks to appear.
- `dist/` is git-ignored: a fresh checkout has no compiled assets until `npm install`
  + a build.
- Run `composer`-free — there is no PHP dependency manager; everything is vanilla WP + ACF.
- `base/_base.scss` styles bare `p` (`font-size: 1.6em; color: #666`). Any `<p>` with its
  own class must set `font-size` / `color` explicitly (or `inherit`) — otherwise it
  silently ignores the parent's size (this bit the footer copyright).
- Sizes use `em` on a 62.5% root (10px): `1.4em` = 14px. Font sizes inside an element
  that already sets `em` compound — set them on the leaf element.
